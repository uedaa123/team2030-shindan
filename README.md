# チーム2030 プロジェクト診断 ／ 公開用サイト

引継ぎ資料 `HANDOFF_チーム2030診断ツール.md` のプロトタイプを、そのまま公開できる形に組み直したもの。
7問に答えると、地域条件と性格特性に近い実在事例と企画のかたちが出る。1人3〜5分。

素のHTML/CSS/JS。ビルド不要、外部CDNなし、フレームワークなし、localStorage不使用（引継ぎ資料 §9）。

---

## ファイル構成

```
index.html                  公開用。data/cases.json を fetch する
config.js                   ★運営が触るのはここだけ（データの場所・記録先・質問数）
assets/style.css            見た目
assets/app.js               設問・スコアリング・結果・コピー・記録
data/cases.json             事例113件。差し替えはこのファイルを上書きするだけ
build.mjs                   オフライン配布用の1ファイル版を吐く
dist/
  TEAM2030_プロジェクト診断_offline.html   ↑の出力。file:// で直接開ける
tools/
  verify-scoring.mjs        配点をいじったときの必須チェック（§5）
  tag-report.mjs            タグの偏りを数える（§7-1 の目視作業の入口）
  gas-endpoint.gs           回答をスプレッドシートに貯めるGASスクリプト（§8-③）
```

## 動かす

### 手元で見る

`index.html` を **file:// で直接開くと動かない**。`data/cases.json` の fetch が CORS で落ちるため
（そう表示される）。手元の確認は次のどちらか。

ローカルサーバーを立てる：

```bash
npx serve .
```

または、データ埋め込み版を開く（ダブルクリックでよい）：

```
dist/TEAM2030_プロジェクト診断_offline.html
```

### 埋め込み版を作り直す

`assets/` か `data/` を直したら、必ず作り直す。中身は公開用と同じものが1枚に入るだけ。

```bash
node build.mjs
```

## 公開する

### いま公開されている場所

| | |
|---|---|
| 公開URL | **https://uedaa123.github.io/team2030-shindan/** |
| リポジトリ | https://github.com/uedaa123/team2030-shindan （**public**） |
| Claudeアーティファクト版 | https://claude.ai/code/artifact/bb37437a-0431-4cfa-8054-6eb2cbf3faf6 （非公開・Claudeアカウントが要る） |

公開URLはログイン不要で誰でも開ける。2026-09-14に植田さんの判断で公開した。

**リポジトリが public なので、`data/cases.json`（事例113件）も誰でも落とせる状態にある。**
引継ぎ資料 §10 が「113件の事例集と各種解釈は有料コンテンツの一部で、全公開は運営判断が要る」
と書いているのはこの状態のこと。運営の判断でこれを止めるときは、リポジトリを private にすると
Pages も止まる（無料プランの場合）ので、UTAGE か Netlify に移すことになる。

`robots.txt` と `<meta name="robots" content="noindex">` を置いてあるので、検索には出ない。
ただし**検索避けであって、アクセス制限ではない**。URLを知っていれば誰でも開ける。

### 更新のしかた

`main` に push すれば1〜2分で反映される。

```bash
node build.mjs
git add -A && git commit -m "..." && git push
```

`node build.mjs` を先に流すのを忘れないこと（`dist/` の埋め込み版が古いままになる）。

### もう1つの選択肢：Netlify

リポジトリを公開したくない場合は、このフォルダごと
[app.netlify.com/drop](https://app.netlify.com/drop) にドラッグ＆ドロップ。
アカウント不要で数秒でURLが出る。**未ログインのサイトは一定期間で消えるので、
無料アカウントは作っておく**（固定URL・差し替え・削除ができるようになる）。
`_headers` はNetlify用の設定ファイルで、Pages では何もしない。

### 段階2：本番（UTAGEの会員エリア）

UTAGEにカスタムHTMLブロックがあれば `dist/...offline.html` の中身をそのまま貼れる（1ファイルなので
外部ファイルの参照がいらない）。なければ Netlify のURLを会員ページから iframe で呼ぶ。

**会員だけがアクセスできる状態にする（完了条件2）のは、このコードの外側の話。**
いまの GitHub Pages はURLを知っている人なら誰でも見られる。UTAGEの会員エリアに入れるか、
Netlifyのパスワード保護（有料プラン）を使うか、どちらかを運営と決めること。

## 運営がやること

### 事例を足す・直す

`data/cases.json` の `items[]` に足すだけ。コードは触らなくてよい（完了条件4）。
必須のキーは `id / src / title / cat / summary / step / place / feat / issue / wd / yn / cost / time`。
書式は引継ぎ資料 §4 のまま。直したら `node build.mjs` で埋め込み版も作り直す。

### 回答を記録する（完了条件5）

1. `tools/gas-endpoint.gs` の手順どおりGASをデプロイする
2. 出たURLを `config.js` の `logEndpoint` に貼る

空のままなら送信は一切しない。ツールは普通に動く。

記録されるのは3種類。

| イベント | いつ | 使いみち |
|---|---|---|
| `start` | 最初の選択をタップした時 | 「開いたが結果まで到達していない人」＝脱落の予兆（§8-③） |
| `result` | 結果画面が出た時 | 7問の回答・提示された上位5件のID |
| `copy` | コピーボタンを押した時 | 次の行動まで進んだ人の数 |

GASの `未到達のセッション()` を実行すると、start だけで result が無い人が出る。

### 質問数を切り替える

`config.js` の `questionSet` を `"short"` にすると3問版（地域・気になること・時間とお金）になる。
URLに `?q=3` を付けても同じ。

**どちらを使うかは運営未確定**（引継ぎ資料 §8-⑤）。キックオフでその場で触らせるなら3問、
2週目の仮プロジェクト決めで使うなら7問。3問版では勇誠義礼とウェルスダイナミクスを聞かないので、
結果画面からもその2つのブロックが消える（当てずっぽうで表示しない）。

## 開発者がやること

### 配点を変えたら

**必ずこれを流す。** 引継ぎ資料 §5 が要求している「4タイプ×3地域で結果が変わること」の確認。
`assets/app.js` の `score()` をそのまま呼んでいるので、配点を変えれば結果もここに出る。

```bash
node tools/verify-scoring.mjs
```

誰がやっても同じ5件が出るようになっていたら、非ゼロで落ちる。

### タグを直すとき（§7-1）

```bash
node tools/tag-report.mjs
node tools/tag-report.mjs issue 地域の魅力が知られていない
```

数えるだけで、何も書き換えない。直すのは `data/cases.json` で、人がやる作業。

いま数えると、いちばん効いていないのは `place` だった。
「小さな町・村」93件、「地方都市の市街地」93件、「中山間・農山漁村」90件で、
**113件中80%超にそれぞれ付いている**。地域規模を選んでもほぼ全事例が15点をもらうので、
実際 `verify-scoring.mjs` を流すと、義タイプと礼タイプは3つの地域で上位5件がまったく同じになる。
`issue`（59件）や `yn`（56件）より先に、ここを間引くほうが結果は変わる。

## いまの状態

### できていること

- 7問・1問1画面・進捗バー・戻る。単一選択はタップした瞬間に次へ（§3のまま変えていない）
- 結果画面：条件サマリー／推薦5件／いまは少し届かないもの2件／ウェルスダイナミクス／勇誠義礼／お金のチェックリスト
- **結果のワンタップコピー**（§8-①・完了条件3）。結果画面の上と下の2か所に置いた。
  `navigator.clipboard` が使えない環境では textarea + `execCommand` に落ち、それも失敗したら
  「コピーされる内容を見る」を開いて手で選べる
- 事例データの外部化（§8-②・完了条件4）。オフライン配布用の埋め込み版はビルドで吐く二本立て
- 回答の記録の口（§8-③・完了条件5）。GASスクリプト同梱、`logEndpoint` が空なら送信しない
- 3問版への切り替え口（§8-⑤）。既定は7問のまま
- スマホ幅375px前提。タップ領域は48px以上。`:focus-visible` のアウトラインは残してある
- ダークモード対応。端末の設定に追従する

### できていないこと

- **実機（iOS Safari / Android Chrome）での確認**（完了条件1）。**最初にやること。**
  手元で確認できたのはここまで：375px幅と1024px幅で7問→結果まで通し、横スクロールが出ないこと
  （`scrollWidth` が画面幅を超えないこと）、3問版で勇誠義礼とウェルスダイナミクスのブロックが
  消えること、`data/cases.json` が無いときにエラー画面が出ること、埋め込み版が動くこと
- **コピーボタンの実動作**。検証に使ったブラウザはクリップボードを許可しない設定で、
  `navigator.clipboard` も `execCommand("copy")` も両方ブロックされた（`clipboard-write: denied`）。
  そのときフォールバックが働いて本文が開き、手で選べる状態になることまでは確認した。
  **HTTPSの実機でワンタップでコピーできるかは未確認。実機確認のときに必ず一緒に見ること**
- **会員だけがアクセスできる状態**（完了条件2）。ホスティング側の設定で、コードの外
- **タグの目視修正**（§7-1）。自動タグ付けの偏りはそのまま残っている。
  `issue`「地域の魅力が知られていない」59/113件、`wd`「サポーター」59/113件、
  `place` は3つの規模がそれぞれ80%超の事例に付いている。
  `node tools/tag-report.mjs` で数えられるようにはしたが、**どのタグを落とすかは人の判断**なので手を付けていない
- **`cost` と `time` の見直し**（§4）。難易度からの機械換算のままで、根拠がない
- 運営への確認事項（§7-2）：勇誠義礼の腕組み対応表／16タイプの残りの軸／使用タイミング

## 配色と書体を変えた理由（§9 の「変える場合は理由を添えること」）

2026-09-14、植田さんの指示で「AIで作った感が強い。TEAM2030らしくカラフルに」。
プロトタイプの明朝＋深緑＋朱鷺色から、次に変えた。

**色は飾りではなく索引にした。** 「気になっていること」10項目に固有の色を割り当て
（`--h0`〜`--h9`、`data/cases.json` の `issues` と同じ並び）、選んだ課題の色が
そのまま結果画面の事例カードの上辺に出る。カードの色は「その事例が、自分の選んだ
どの課題に効くか」で決まる。勇誠義礼の4タイプにも固有色がある（勇＝朱、誠＝青、義＝橙、礼＝桃）。

各色は2段持ち。`--hN` は文字にも使うので白地で読める濃さ、`--hNv` は面を塗る鮮やかな側。
チップの白文字は必ず `--hN` の側に乗せている。課題を増やすときは `style.css` に
`--h10` / `--h10v` を足せばよく、無ければ既定色に落ちる（`app.js` の `hue()`）。

**書体**は見出しを Zen Maru Gothic（丸ゴシック）に、本文は端末のゴシックのまま。
明朝→丸ゴシックが「ポップさ」のいちばん効く一手で、本文を触らないぶん読みやすさは落ちない。

**新しく増えた依存が1つある。** Google Fonts の Zen Maru Gothic を `<link>` で読んでいる。
§9 の「外部CDNなし」からは外れる。フォールバックに Hiragino Maru Gothic ProN 以下の
端末書体を積んであるので、**読めなくても表示は崩れない**（UTAGEの埋め込みで外部読み込みが
止められている場合もここで吸収される）。見出しだけ・1ウェイトだけに絞って重さは抑えたが、
外部読み込みを一切許さない方針なら `index.html` と `build.mjs` の `<link>` 3行を消せば戻る。
